# SEMS2 운영 개선 내역

## 적용 범위

증빙 첨부·연결, ERP·외부 프로그램 연계, 협력사 관리의 확장은 제외했습니다. 기존 기능을 삭제하지 않고 내부 수집·입력·검토·집계·마감 흐름과 저장 신뢰성을 개선했습니다.

| 업무 | 개선 내용 |
|---|---|
| 수집 요청 | 법인 아래 사업장별 요청·미입력·제출·확정 현황을 월별로 표시하고 항목에서 입력·조회로 이동합니다. |
| 입력 | 실제값·실제 0·해당 없음·추정값을 구분합니다. 빈칸을 0으로 처리하지 않으며 추정·해당 없음에는 설명이 필요합니다. |
| Excel·CSV | 시트 선택, 열 자동 연결과 수동 수정, 파일 내부/기등록 중복 검사, 전체 오류 확인과 오류 행 CSV, 정상 행 선택적 등록을 지원합니다. |
| 온실가스 산정 | 단위의 차원과 배출계수 유효기간을 확인합니다. 신규 산정 시 계수 식별자·내용 버전·출처·기간을 함께 보존합니다. |
| 검토 | 목록과 상세 정보를 한 화면에 표시합니다. 근거·산정, 검증, 변경·검토 정보 탭에서 확인하고 의견·보완 요청·확정을 처리합니다. |
| 품질 확인 | 문제의 관련 자료로 이동하고 확인 사유와 처리 상태를 기록합니다. 값이 바뀌면 기존 확인 결과를 그대로 재사용하지 않습니다. |
| ESG 집계 | 조직별 기간 집계와 조직 간 집계를 분리합니다. 기말 인원은 각 조직의 기말값을 합치며, 비율은 분자·분모로 다시 계산합니다. |
| 보고 | 확정자료의 포함 조직·기간, 추정값·실제 0·해당 없음·누락과 집계 경고를 확인합니다. 연결한 공시 항목의 실제 자료 준비 상태를 표시합니다. |
| 마감 | 대상 사업장·기간의 미입력·미확정·유효하지 않은 자료를 검사합니다. 마감된 요청의 범위나 자료는 먼저 재개한 뒤 수정해야 합니다. |
| 저장 | 서버 revision 비교로 동시 저장의 덮어쓰기를 차단합니다. 충돌 시 내 변경사항 내려받기와 최신 자료 불러오기를 제공합니다. |
| 변경 이력 | 서버가 실제 저장한 전후값·로그인 사용자·DB 시각을 별도 추가 전용 이력에 기록하며 관리자 화면에서 조회·내보내기 합니다. |

## 계산과 호환성

- 월별 활동자료에는 해당 월 전체에 유효한 계수만 적용합니다. 계수의 발표 연도만으로 만료시키지 않습니다.
- 호환되는 단위만 변환합니다. 표준상태 `Nm³`와 일반 부피 `m³`, 부피와 질량처럼 추가 조건이 필요한 변환을 임의로 하지 않습니다.
- 계수 설정 변경은 기존 저장된 산정값을 소급 수정하지 않습니다. 기존 자료에 없던 출처·버전은 임의로 만들어 붙이지 않으며 기록 없음으로 표시합니다.
- 과거 법인 단위 요청 키를 읽을 수 있습니다. 등록된 사업장이 여러 개인데 한 사업장만 제출한 경우 전체 완료로 보이지 않도록 계산합니다.
- 비율에 필요한 분자·분모가 없는 다조직 집계는 그럴듯한 합계나 단순 평균으로 대체하지 않고 집계 불가와 경고를 표시합니다.
- 과거에 잘린 클라이언트 이력은 복원하지 않습니다. 새 서버 이력은 마이그레이션 적용 이후부터 남습니다.

## 운영 반영 전 확인

이 작업에서는 운영 Supabase 데이터나 Vercel 배포를 변경하지 않았습니다. 새 SQL을 먼저 적용해야 이 버전의 저장 API를 사용할 수 있습니다. [저장·이력 적용 안내](workspace-integrity-rollout.md)의 순서를 따르세요.

브라우저 검증은 로컬 서버에서 가상 사용자·샘플 업무 자료와 네트워크 응답을 사용합니다. 실제 Supabase 로그인·RLS·배포 환경의 검증을 대체하지 않습니다. 별도 PostgreSQL 실행 환경에서 마이그레이션과 원자적 저장·충돌·재시도·변경 이력·권한을 검증합니다.

JSON workspace 전체를 저장하는 현재 구조는 유지했습니다. 서로 다른 자료의 동시 편집도 공유 범위가 바뀌면 충돌할 수 있으며 자동으로 병합하지 않습니다. 충돌 화면에서 로컬 변경을 보관하고 최신 자료에 필요한 수정을 다시 적용합니다.

검토 권한은 기존 관리자 역할을 사용합니다. 별도 검토자 역할, 실시간 외부 알림 발송, 조직·사용자 관리 API의 별도 감사 이력은 이번 변경에 포함하지 않았습니다. GHG 마감의 수집 단위는 요청된 사업장·월·Scope이며 개별 배출원의 필수 목록을 새로 정의하지 않았습니다.

## 확인한 결과

- 전체 CI 명령 `npm test`: 기존 Vinext 빌드·산출물 검사와 회귀 테스트 **81개 통과**.
- Vercel용 `npm run build:vercel`: Next.js 프로덕션 빌드와 타입 검사 통과.
- 저장소 전체 ESLint: 오류·경고 0. 로컬 검증용 생성 폴더는 검사에서 제외했습니다.
- 격리 PostgreSQL(PGlite): 마이그레이션 반복 적용, 여러 범위 원자 저장, 동시 revision 충돌, 동일 요청 재시도, 중간 실패 전체 취소, 변경 이력 수정·삭제 금지, 직접 쓰기 권한 차단 통과.
- Edge/Playwright 로컬 브라우저: 검토 의견 필수, 반려·확정 저장, 음수 승인 차단, 품질 확인 사유 저장, 서버 이력 전후값, 저장 충돌 시 입력 보존·내려받기, 390px 모바일 가로 넘침 없음 확인.
- Excel 브라우저 흐름: 시트 선택·열 연결, 빈칸 검증, 파일 내부 및 기등록 중복 제외, 오류 CSV, 정상 행과 실제 0 및 계수 기록 저장, 사업장 현황 표시 확인.

위 브라우저 테스트는 네트워크를 가상 응답으로 대체한 UI 검사입니다. 실제 운영 계정과 운영 DB를 사용한 검증은 배포 단계에서 별도로 수행해야 합니다.
- 추가 브라우저 확인: 사업장·월·Scope 유지, 신규 실제 0과 계수 기록 저장, 비율 25/100 → 25% 자동 표시·저장, 누락·미확정 마감 차단, 마감 품질 확인의 읽기 전용 처리 통과.
- CSV 내보내기는 수식으로 해석될 수 있는 문자열을 보호하고 실제 숫자형 음수는 유지합니다. 관련 회귀 테스트 3개를 포함합니다.
